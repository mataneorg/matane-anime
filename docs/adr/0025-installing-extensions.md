# 25. Installing, updating and removing extensions: two steps, atomic, checked on every load

Status: Accepted (2026-10-09)

## Context
Installing runs someone else's code, so the user must see what they are installing before anything is written, a failed install must not leave a half-written extension, and a file changed on disk must not run (docs/PRD.md EXT-8, §10.2).

## Decision
- **Two steps.** `extensions.prepareInstall` checks, in order: the entry exists, it is compatible (`apiVersion`, `minAppVersion`), the id is not provided by a dev folder or installed from another repository ([0026](0026-origin-aware-registry.md)); then it downloads the archive and icon with the size caps and verifies them in memory ([0024](0024-extension-repositories.md)). Each failure becomes a readable `AppError` (`unsupported` for a version that is too new, `forbidden` for a conflict, `invalid_input` for integrity, `network`/`offline`). It returns what the dialog shows (repository and trust, API version, languages, size, SHA-256, warnings `unverified`, `unsigned`, `nsfw`) and a random 128-bit **token**, valid 5 minutes on an injected clock, single use (consumed even if the install then fails), at most 5 kept, one per extension id. `extensions.install(token)` re-checks that the repository still exists and that there is no conflict, then writes.
- **Atomic swap**, one install at a time (a promise queue): remove stale `<id>.tmp` and `<id>.old`; write `<id>.tmp/{manifest.json,index.js,icon.png}`; rename `<id>` to `<id>.old` if it exists; rename `.tmp` to `<id>`; load it through the registry, which writes the database row (origin `repo`, repository, install folder, version, SHA-256 of `index.js`); delete `.old`. If any step fails, or the load does, the previous version is put back (reloaded from its old row) or a first install is removed, and the user is told nothing was changed. `recoverInterrupted()` at startup removes `*.tmp`, restores `*.old` when `<id>` is missing and deletes it otherwise.
- **Updates need no dialog**: only to a strictly newer version from the repository the copy came from, with the same verification and swap; `updateAll` returns what worked and what failed. Updates are never filtered by the 18+ or language settings, so installed extensions always get fixes. After an install or update, `migrateUrl` runs at once ([0026](0026-origin-aware-registry.md)).
- **Integrity at load.** Before anything reaches the sandbox the registry checks that the bundle is readable and at most 2 MB, that `sha256(index.js)` equals the stored hash, that the manifest id equals the row's and that `apiVersion` is not above the app's. Otherwise the record has `status: 'error'` ("The installed files were changed; reinstall the extension") and the code never runs. `manifest.json` is not covered by the hash, only its id and `apiVersion` are checked. Installed extensions are not polled for changes.
- **Uninstall**: unload from the host, delete `userData/extensions/<id>` (and `.tmp`/`.old`; never a path outside that folder, whatever `install_dir` says), delete the `extensions` row (preferences and storage cascade), clear the `persist:ext-<id>` session and the network state. **Sources and anime stay**, shown as "not installed", and the `migrateUrl` version baseline is kept so reinstalling an older version still compares. Dev extensions are removed by removing their folder, not by uninstall.

## Consequences
- A repository that changes an archive without a refresh gives the user a hash or size error until the next refresh.
- `install_dir` in the database is trusted for loading (the hash still protects `index.js`) but not for deleting.
